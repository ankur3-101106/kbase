# Git Commit & Push Guidelines (`COMMIT.md`)

This guide defines the standards, pre-commit verification steps, and exact terminal commands for properly reviewing, documenting, committing, and pushing changes to the remote GitHub repository across **Windows 11**, **Arch Linux**, and **Android (Termux)**.

---

## 1. Commit Message Convention

`kbase` adheres to a lightweight [Conventional Commits](https://www.conventionalcommits.org/) format. Clear, structured commit messages make the repository history easily searchable via `git log --grep` and simplify conflict resolution.

### 1.1 Format Structure

```text
<type>(<scope>): <short imperative description>

[optional body explaining context or rationale]
```

### 1.2 Allowed Commit Types

| Type | When to Use | Example |
| :--- | :--- | :--- |
| `feat` | Adding a new note, major topic area, template, or tool. | `feat(cybersecurity): add windows memory forensics notes` |
| `docs` | Editing, refining, expanding, or revising existing notes. | `docs(education): refine b-tree complexity explanation` |
| `fix` | Correcting technical inaccuracies, broken links, or formatting bugs. | `fix(links): resolve relative link in search guide` |
| `refactor`| Reorganizing directories, renaming notes to kebab-case, or restructuring. | `refactor(taxonomy): reorganize networking notes into subdomains` |
| `chore` | Routine maintenance, archiving old notes, updating `.gitignore` or tools. | `chore(archive): move completed 2025 project records` |
| `sync` | Automated daily synchronization commits (generated by `kbase-sync.sh`). | `sync(windows): sync notes 2026-10-12 00:00 +0530` |

### 1.3 Recommended Scopes

Use the topical area or root directory as the scope:
- `cybersecurity` (or sub-scopes: `dfir`, `pentest`, `websec`)
- `systems` (or `arch`, `windows`, `network`)
- `education` (or `dsa`, `db`, `exam`)
- `procedures` (or `sop`, `sync`)
- `projects`
- `resources`
- `templates`
- `tools`

### 1.4 Commit Rules
1. **Imperative Mood:** Use "add", "update", "fix", not "added", "updating", "fixes".
2. **Lowercase Description:** Keep the first line concise (under 72 characters) and lowercase after the colon.
3. **No Secrets in Messages:** Never include sensitive hostnames, internal IPs, or private details in commit messages.

## 2. Pre-Commit Verification Checklist

Before staging and committing manual changes, run through this quick checklist:

- [ ] **1. Validate Repository Integrity:** Run the local validator to check for broken links and frontmatter errors:
  ```bash
  python tools/validate.py
  ```
- [ ] **2. Inspect Working Tree:** Verify only intended files were modified:
  ```bash
  git status
  ```
- [ ] **3. Security & OPSEC Audit:** Ensure no `.env`, private keys, API tokens, passwords, or raw `.pcap`/`.mem` dumps are staged.
- [ ] **4. Check Formatting:** Ensure filenames are lowercase and hyphenated (`kebab-case.md`).

## 3. Step-by-Step Commit & Push Workflow

### Step 1: Check Modified and Untracked Files
```bash
git status
```

### Step 2: Stage Your Changes
Stage specific files or all changes:
```bash
# Stage all changes (new, modified, deleted)
git add -A

# Or stage specific files
git add knowledge/cybersecurity/dfir/new-note.md
```

### Step 3: Inspect the Staged Diff
Review exactly what is about to be recorded:
```bash
git diff --cached --stat
```

### Step 4: Create the Commit
```bash
git commit -m "feat(dfir): add volatile memory acquisition procedure"
```

### Step 5: Pull Remote Changes with Rebase
Before pushing, always pull remote changes using `--rebase` to integrate any commits made from other devices (e.g., mobile captures synced overnight):
```bash
git pull --rebase origin main
```

*(If a rebase conflict occurs, follow the instructions in [`procedures/synchronization-and-conflict-resolution.md`](procedures/synchronization-and-conflict-resolution.md)).*

### Step 6: Push to GitHub Remote
```bash
git push origin main
```

## 5. Coexistence with Automated Sync (`kbase-sync.sh`)

Your automated synchronization task runs daily at 12:00 AM on Windows and Android:
- **Lock Protection:** `kbase-sync.sh` creates `.git/kbase-sync-lock`. If you push manually while the scheduled task is running, Git will safely wait or report the lock.
- **Always Rebase:** Manual pushes should always use `git pull --rebase origin main` so your manual commits sit cleanly on top of scheduled sync commits without creating empty "Merge branch 'main'" commits.
- If an automated sync fails due to an incomplete rebase, consult [`procedures/troubleshooting/git-sync-failures.md`](procedures/troubleshooting/git-sync-failures.md).
